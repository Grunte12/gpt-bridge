# Interface or UI mockup

- State device, viewport, user, task, product state, information hierarchy, and
  the single interaction the screen must explain.
- List every required region and exact visible label. Describe layout and
  alignment as a wireframe before adding style.
- Use realistic density and familiar controls. Include empty, error, loading,
  or success state only when requested.
- For an existing product, edit a screenshot and preserve the design system,
  shell, spacing rhythm, navigation, and unaffected content.
- Treat the result as a concept image, not working UI. If exact pixels,
  selectable text, responsive behavior, or implementation is required, build
  it with code instead.
- Forbid illegible microcopy, duplicated navigation, impossible controls,
  decorative device clutter, unrelated logos, and watermarks.
